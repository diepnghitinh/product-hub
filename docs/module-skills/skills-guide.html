Cách dùng

Điểm vào: gõ /product-os-architecture để lấy bản đồ tổng, rồi nhảy sang skill module cụ thể.

Khi làm việc trên một vùng: gõ đúng skill của nó — ví dụ sửa board Kanban → /module-teams + /module-issues; làm tài liệu realtime → /module-docs + /module-collab.

Đã commit được: các skill nằm trong repo nên cả team dùng chung; mỗi skill đã được 1 agent thứ hai verify đối chiếu source.

Đã audit lại: 20 agent rà toàn bộ đối chiếu source — vá 63 gap tại chỗ (thiếu quan hệ/field/endpoint, sai lệch) + 23 quan hệ 2 chiều còn thiếu; 5 đề xuất bị loại vì source không chứng minh (không bịa thêm).

4 ứng dụng · nền chung

backend — NestJS 11, MongoDB/Mongoose, mọi route dưới /v1/*, chia 3 lớp DDD (presentation · application · infrastructure). Guard toàn cục: JwtAuthGuard → RolesGuard.  frontend — React+Vite, mỗi feature một thư mục src/features/*.  saas-admin — React+Vite, console cho vendor, chỉ nói chuyện với /v1/platform (token riêng).  collab — server Hocuspocus/Yjs riêng, đồng bộ CRDT nội dung doc.  Mọi aggregate mang tenantId để cách ly multi-tenant.

Bản đồ quan hệ — issue ở trung tâm

1 · Nhân — Issue & vệ tinh

8 module

Task và Bug là một entity issue (một collection, một API, một hook factory) phân biệt bằng kind. Nhóm này là các mặt và phần đính kèm của nó.

module-issues

Issues

Record đa hình hợp nhất Task+Bug: một collection issues, phân biệt bằng kind. Bản ghi trung tâm mọi thứ khác trỏ vào.

Quan hệ chính
  • teams — teamId + statuses/labels/custom-fields đến từ team
  • cycles — cycleId, rollover sprint
  • roadmaps — roadmapItemId nối task với backlog
  • reports — bug mang caseId/reportId
module-bugs

Bugs

Defect report: mức severity, ảnh/quay màn hình, link về test-case. Board /bugs, phục vụ qua /v1/issues?kind=bug.

Quan hệ chính
  • issues — nhà thật của nó (một trong hai kind)
  • reports — reportId nối bug về test-case
  • issue-links — quan hệ blocks/duplicate với issue khác
module-tasks

Tasks

Việc kỹ thuật/sản phẩm, size theo thang Fibonacci, có sub-task. Nuôi board team, "My Tasks", và Personal board mỗi user.

Quan hệ chính
  • issues — abstraction cha; dùng chung makeIssueHooks
  • teams — cột board = TeamStatusConfig
  • roadmaps — nối tới backlog item
module-cycles

Cycles (Sprint)

Nhịp sprint của team: cửa sổ dài cố định. Chạy auto (scheduler mint + rollover) hoặc manual; theo dõi scope/completed + burn-up.

Quan hệ chính
  • teams — cấu hình nhịp nằm trên TeamEntity
  • issues — cycleId, rollup, rollover
  • admin — TeamCyclesEditor là UI duy nhất chỉnh nhịp
module-issue-links

Issue Links

Quan hệ có kiểu, có hướng giữa 2 issue: blocks / is-blocked-by / parent-of / related-to / duplicate-of. Cross-type (bug chặn task).

Quan hệ chính
  • issues/tasks/bugs — validate 2 đầu qua repo issue chung
  • Không module nào khác đọc/ghi nó — quan hệ thuần 2-issue
module-labels

Labels

Pill tag tự do theo màu, định nghĩa theo team (không có built-in, không list toàn cục). Áp lên task/bug qua labelKeys.

Quan hệ chính
  • teams — labels là field của Team, sửa ở Settings → Teams
  • tasks/bugs — mang labelKeys, render LabelChips
module-custom-fields

Custom Fields

Field tự định nghĩa kiểu Jira (Environment, Story Points…) hiện thành property row trên mọi bug/task của team. Định nghĩa thuộc team, giá trị theo issue.

Quan hệ chính
  • teams — CustomFieldConfig[] nằm trên Team.customFields
  • bugs/tasks — lưu giá trị vào issue.customFields
module-reactions

Reactions

Emoji reaction nhanh (palette cố định, toggle) gắn lên issue hoặc roadmap item. Pill đếm số + tooltip ai đã react.

Quan hệ chính
  • issues — ReactionBar dưới Description ở detail
  • roadmaps — cùng bar với ReactionTargetType.RoadmapItem

2 · Lập kế hoạch

3 module

"Đang cược vào gì" (Roadmap/RICE) và "thành công trông ra sao" (OKR), gộp trên một trang tab.

module-roadmaps

Roadmaps

Board backlog/ưu tiên, chấm điểm RICE (reach×impact×confidence/effort), cột "pool" tùy biến. Xem dạng Kanban / bảng RICE / Gantt. Chia sẻ công khai được.

Quan hệ chính
  • issues — task/bug mang roadmapItemId để thực thi item
  • milestones — item link tới OKR (objectiveId/keyResultId)
  • public — PublicRoadmapsController phục vụ view read-only
module-milestones

Milestones (OKR)

OKR = title + timeframe chứa objectives, mỗi cái có key results. Progress cuốn lên: KR → objective (có trọng số) → milestone.

Quan hệ chính
  • roadmaps — roadmapIds[] nối tới nhiều roadmap
  • planning — là tab "OKRs" của trang planning
module-planning

Planning

Chỉ là vỏ trang mỏng, không có backend riêng: đặt Roadmaps và OKRs sau một dải tab (/roadmaps · /okrs).

Quan hệ chính
  • roadmaps + milestones — render 2 panel của chúng
  • Không nối team/my-team — chỉ ở trang cấp workspace

3 · Testing / QA

4 module

Phía "Testing" của app (tách khỏi issue-tracker): Project → Report (test-case) → bug được raise từ đó.

module-projects

Projects

Container cấp cao nhất của "Testing": mỗi initiative một Project, có badge environment (dev/staging/prod), nest các feature report bên dưới.

Quan hệ chính
  • reports/groups — Project sở hữu report + folder nhóm
  • public — chia sẻ project lộ ra test reports
  • tenants/auth — scope theo tenant, validate quyền
module-reports

Reports / Test-cases

Tài liệu test theo feature: các section (overview/screenshot/cards/steps/bullets/ordered) + bảng test-case có kết quả (Passed/Failed…). Cuốn lên progress của project.

Quan hệ chính
  • bugs — bug raise against test-case qua reportId (một chiều)
  • projects — report scope 1:1 theo projectId
  • audit-log — đổi kết quả test-case được ghi lịch sử
  • public — test report lộ ra qua link chia sẻ project
module-groups

Groups

Folder có thứ tự, admin đặt tên, scope trong một project (vd "1 · Authentication") để gom các Report của project trong sidebar.

Quan hệ chính
  • reports — Report mang groupId; kéo-thả đổi group
  • projects — luôn scope theo projectId (route lồng)
module-audit-log

Audit Log

Lịch sử append-only "ai đổi gì" trên test-case/report — hiện tập trung ở thay đổi kết quả test-case, cho cả user và CI/API.

Quan hệ chính
  • reports — đường ghi thật; đổi trùng giá trị thì không ghi
  • projects — entry scope theo project
  • public — endpoint CI công khai ghi kèm actor API

4 · Tài liệu & cộng tác

5 module

Kiến thức viết ra (docs realtime), và lớp phản hồi bám theo mỗi issue.

module-docs

Docs

Knowledge base kiểu Notion: cây page, mỗi page thân HTML, đính vào issue/roadmap, version tay, xuất PDF, publish read-only. Thân page sửa realtime qua server collab.

Quan hệ chính
  • collab — engine realtime; giữ CRDT Yjs, ghi HTML về docpages.content
  • activity — comment neo vào đoạn trích trong page (resolve được)
  • issues/roadmaps — page đính vào bug/task hoặc roadmap item
module-collab

Collab (realtime)

Service thứ tư (cạnh db/api/web). Cho 2 người co-edit thân page không mất dữ liệu: thân page là CRDT Yjs, relay caret/selection (awareness).

Quan hệ chính
  • docs — lý do tồn tại; chỉ giữ CRDT + đồng bộ docpages.content
  • auth — dùng cùng JWT của REST API (JWT_SECRET phải khớp)
module-activity

Activity

Một engine comment-thread dùng lại cho 3 chủ thể: issue, doc page (neo vào đoạn trích), roadmap item. Không phải audit đổi field — chỉ là thread 1 cấp.

Quan hệ chính
  • issues/bugs/tasks — một thread chung cho cả bug & task
  • docs/roadmaps — cùng engine cho comment page & roadmap item
  • inbox — chỉ mention bug mới báo inbox (v1)
  • webhooks — comment-mention bắn COMMENT_MENTION; storage — ảnh đính trong comment
module-inbox

Inbox

Trung tâm thông báo kiểu Linear: gộp (1) comment @mention bạn + (2) bug đang gán cho bạn. Read model không có store riêng, tính live mỗi lần gọi.

Quan hệ chính
  • bugs/issues — mục "assigned" query issue kind=bug
  • activity — mention lấy từ comment store
  • users — read-state (inboxSeenAt) lưu trên user doc
module-favourites

Favourites

Ghim issue / roadmap item / doc lên sidebar. Mỗi ghim là snapshot denormalized (title + route) để render tức thì không cần fetch lại.

Quan hệ chính
  • users — favourites lưu inline trên UserEntity (không store riêng)
  • issues/roadmaps/docs — 3 loại đối tượng ghim được

5 · Con người & truy cập

6 module

Đơn vị sở hữu (team), tài khoản, đăng nhập, và các view theo người.

module-teams

Teams

Team sở hữu đúng một list issue (bug hoặc task) và mọi thứ board cần: cột statuses, labels, custom-fields, nhịp cycle. Workspace luôn có sẵn qc + engineering.

Quan hệ chính
  • bugs/tasks — board đọc cột từ team.statuses, không hardcode
  • cycles — nhịp sprint nằm trên team
  • labels/custom-fields — dùng chung cho mọi issue của team
module-users

Users

Tài khoản thành viên tenant: admin CRUD, tự đổi password/avatar, "last online". Sở hữu cột Personal board riêng mỗi user (personalStatuses).

Quan hệ chính
  • auth — JwtPayload lái mọi route scope theo tenant
  • tasks — personalStatuses nuôi /tasks/personal
  • favourites/inbox — đều lưu inline trên user doc
module-auth

Auth

Đăng nhập email/mật khẩu kiêm bootstrap workspace: register tạo tenant + admin đầu tiên; login trả JWT. Không có lớp infra riêng.

Quan hệ chính
  • tenants — register tạo tenant; re-check isSuspended
  • teams — EnsureDefaultTeamsUseCase khi đăng ký
  • Mọi controller khác — JwtAuthGuard/RolesGuard global
module-my-team

My Team

Hàng đợi team nhìn theo người: lưới card workload mỗi người, % hoàn thành (story point + số issue), issue nhóm theo status. App không có model membership — "người" = ai được gán.

Quan hệ chính
  • issues — nguồn dữ liệu duy nhất, tính client-side
  • teams — cột màu đọc từ TeamStatusConfig
module-account

Account

Trang hồ sơ tự phục vụ của chính bạn (/profile): xem identity read-only, đổi avatar, đổi mật khẩu. Không có backend riêng — gọi /users/me/*.

Quan hệ chính
  • users — chủ sở hữu entity + endpoint /users/me/*
  • storage — dialog crop đẩy file qua uploadMedia
module-admin

Admin (frontend)

Màn Settings & People của workspace — không backend riêng. Gộp API nhiều module: team/statuses/cycle/label/custom-field, API keys, MCP, webhooks, storage, quản lý user.

Quan hệ chính
  • teams — mỗi tab "Teams" là một team; sửa statuses/labels…
  • app-settings — tab Webhooks + Cloud Storage
  • api-keys — tab API Keys / MCP

6 · Nền tảng · SaaS · tích hợp

9 module

Lớp multi-tenant, console vendor, và các cổng ra ngoài (chia sẻ, AI, webhook, storage).

module-tenants

Tenants

Tenant = một workspace, ranh giới cách ly mọi aggregate mang tenantId. Không có UI quản lý tenant trong app chính — chỉ từ console saas-admin.

Quan hệ chính
  • auth — check isSuspended mỗi login & request
  • platform — sở hữu toàn bộ HTTP surface quản lý tenant
module-platform

Platform (vendor console BE)

Backend cho app saas-admin, tách khỏi workspace tenant. Operator đăng nhập credential riêng, quản tenant (tạo/suspend), định nghĩa plan + entitlement, gán subscription, tính usage.

Quan hệ chính
  • tenants — tạo TenantEntity + admin đầu, toggle suspend
  • saas-admin — frontend tiêu thụ toàn bộ API này
module-saas-admin

SaaS Admin (app)

App React riêng — back office của vendor. Xem mọi tenant, định nghĩa plan + entitlement kế thừa, gán/đổi/hủy subscription, override theo tenant, theo dõi usage vs limit.

Quan hệ chính
  • platform — tiêu thụ duy nhất API /v1/platform
  • auth — không gian identity riêng (PlatformAdmin)
module-app-settings

App Settings

Một document/tenant: webhook chat, provider cloud-storage, và list default bug/task status (cũ, cấp workspace). Tạo lười khi đọc lần đầu.

Quan hệ chính
  • teams — cột board thật nằm ở team, không đọc từ đây
  • webhooks (cấu hình hook — module này chứa, webhooks gửi)
  • storage — chứa CloudStorageConfig mà storage đọc mỗi lần upload
module-api-keys

API Keys

Admin mint token bí mật/tenant (phk_...) cho client ngoài (chủ yếu AI qua MCP) auth như user thật, không cần JWT. Plaintext hiện đúng một lần; chỉ lưu hash SHA-256.

Quan hệ chính
  • mcp — mọi request MCP guard bằng ApiKeyGuard
  • public — endpoint CI test-case cũng dùng key này
module-mcp

MCP server

Mở Product-OS cho trợ lý AI qua Model Context Protocol: list workspace, search issue, tạo task/bug/backlog/doc — không cần trình duyệt. Đi qua cùng use-case như app web.

Quan hệ chính
  • issues — create_issue gọi CreateIssueUseCase
  • api-keys — auth bằng key; roadmaps/docs — tạo qua use-case
module-webhooks

Webhooks

Bắn thông báo ra Lark/Telegram khi có sự kiện (bug mới, bug được gán, bị @mention). Backend-only, không có REST surface riêng — chỉ gửi.

Quan hệ chính
  • app-settings — chứa cấu hình hook (enable/mapping)
  • issues/activity — nguồn sự kiện BUG_CREATED…
module-storage

Storage / Uploads

User upload ảnh/video/tài liệu lên bucket của tenant (S3/Azure) và nhận URL công khai. Không có file model — pass-through stateless để đính media khắp app.

Quan hệ chính
  • app-settings — đọc CloudStorageConfig mỗi lần gọi
  • bugs/docs/users — attachment, ảnh doc, avatar đi qua đây
module-public

Public / Share links

Link không cần login cho người ngoài xem read-only một board team / roadmap / test report / doc. Cộng một endpoint x-api-key cho CI ghi kết quả test-case.

Quan hệ chính
  • teams/roadmaps/projects/docs — 4 loại được chia sẻ
  • issues/activity — đọc cùng collection app authed ghi
